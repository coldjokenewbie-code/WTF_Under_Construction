| 任務型態 | 預設 | 管道 | 升級條件 | 失敗處理 |
|---|---|---|---|---|

額度規則：
- **任務失敗**（結果不對）與**額度耗盡**（rate limit／quota 錯誤）分開：前者換方法或升一級並重寫交辦；後者降一級或等候，不升級。
- Fable／Opus 是選擇不是階梯：同任務同角色最多升一級一次，升級須寫原因。
- subagent 是否繼承 context 依工具而定，不寫「必然共享」；fresh CLI 仍載同套制度 prompt，獨立性靠自足驗收條件，不靠換模型。

## 3. 我獨立驗收最會找的 3 個失敗點

1. **部署漂移**：repo 改了 GLOBAL，但 `~/.claude/CLAUDE.md` import 的 bundle hash 目錄未重生或舊 hash 殘留，hook 注入舊版。核法：sync 後 bundle 內容 hash 等於 repo 檔；用被搬走的關鍵語句 grep bundle 應為 0 筆。
2. **遷移失真**：逐條 grep 原關鍵語句（`Git_work`、`.retired-`、`startIn`、`'documents'`、`⌘⇧G`、`-g 不可省略`、`Calibri`、`同月同日`、「備份至 archive」）必須在新 playbook 命中；GLOBAL 保留列須同時含觸發詞＋結論＋指標。任一語句兩處皆無＝弱化。
3. **check 假通過**：改部署副本一個位元組、改索引一個描述、刪一個部署檔、暫放重名 skill → 四種各需 exit 1；暫時改名 `~/.gemini` → 應 skip 非 fail；sync 連跑兩次後 `diff -r` 部署樹相同；在 `~/.claude/skills/` 放假目錄 → sync 不刪、check 列孤兒。
