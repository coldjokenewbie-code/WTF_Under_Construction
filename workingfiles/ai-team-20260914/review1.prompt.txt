+def _scalar(value, path):
+    """接受純文字與單/雙引號 scalar；其他 YAML 結構需明確報錯。"""
+    if value.startswith('"'):
+        try:
+            result = json.loads(value)
+        except json.JSONDecodeError as error:
+            raise ValueError(f"{path}: 非法雙引號 metadata") from error
+        if not isinstance(result, str):
+            raise ValueError(f"{path}: metadata 必須是文字")
+        return result
+    if value.startswith("'"):
+        if not value.endswith("'") or len(value) < 2:
+            raise ValueError(f"{path}: 單引號未關閉")
+        return value[1:-1].replace("''", "'")
+    if value.startswith(("[", "{", "&", "*", "!")):
+        raise ValueError(f"{path}: name/description 僅支援文字 scalar")
+    return value

+def read_metadata(path):
+    """讀 name/description；支援單行或 |/> 多行，不引入 YAML 依賴。"""
+    text = path.read_text(encoding="utf-8-sig")
+    match = re.match(r"\A---\r?\n(.*?)\r?\n---(?:\r?\n|\Z)", text, re.S)
+    if not match:
+        raise ValueError(f"{path}: 缺 frontmatter")
+    lines = match.group(1).splitlines()
+    metadata = {}
+    for position, line in enumerate(lines):
+        field = re.match(r"^(name|description):\s*(.*)$", line)
+        if not field:
+            continue
+        key, value = field.groups()
+        if key in metadata:
+            raise ValueError(f"{path}: 重複欄位 {key}")
+        if value in ("|", ">", "|-", ">-", "|+", ">+"):
+            block = []
+            for following in lines[position + 1:]:
+                if following and not following[0].isspace():
+                    break
+                block.append(following.strip())
+            value = " ".join(block)
+        else:
+            value = _scalar(value.strip(), path)
+        metadata[key] = " ".join(value.split())
+    for key in ("name", "description"):
+        if not metadata.get(key):
+            raise ValueError(f"{path}: 缺少或空白 {key}")
+    return metadata

 ## 2. 任務交辦三要素（缺一不派）
 
-每次派工的 prompt 必含（填空範本見 `playbooks/delegation-templates.md`）：
-1. **目標與動機**：要什麼＋為什麼要（動機讓 subagent 遇到意外時能做對的取捨）。
-2. **驗收條件**：可勾選的完成判準，逐條列。「做好做滿」不是驗收條件，「X 檔案存在且含 Y 段落」才是。
-3. **回報格式**：明定回什麼、多長、什麼格式（見下一節回報合約）。
+1. **目標與動機**：要什麼、為什麼；提供執行所需脈絡。
+2. **驗收條件**：可逐條核對的完成判準與允許修改範圍。
+3. **回報格式**：結論、證據、限制與長度；範本見 `delegation-templates.md`。
 
-## 3. 回報合約（subagent 端遵守，指揮官端在 prompt 裡引用）
+## 3. 回報合約
 
-- 只回**結論與判斷**，每個事實附 `檔案:行號`。
-- **禁止**貼大段原文；需要保留的長產物**存檔後回傳路徑**。
-- 回報長度上限預設 120 行（交辦時可另訂）。
-- 失敗就說失敗＋卡在哪＋已試什麼，不硬掰結果。
-- 回報開頭第一行＝一句話結論（成／敗／部分完成）。
+- 第一行說明成功、失敗或部分完成；每個事實附檔案:行號或實際命令輸出。
+- 主對話只收結論與判斷；長產物存檔回路徑，不貼大段原文。
+- 預設最多 120 行，交辦可另訂；失敗需說卡在哪、已試什麼，不捏造成功。

+## 5. 升級與備援上限
+
+**一輪＝一次實際任務執行**。同子任務最多 4 輪：`haiku 1 → sonnet 2 → 高階終局 1`；從 Sonnet 起最多 3 輪，從高階起只有 1 輪。
+
+- Haiku 錯一次就升 Sonnet；Sonnet 第二次必須換方法並重寫交辦，不能原 prompt 重送。
+- Sonnet 兩次仍不符條件，帶完整失敗軌跡（方法、輸出、驗收差距）交 Opus 或 Fable **二選一**終局處理。
+- 高階仍做錯 → 停止自動重試，回報證據與待決；不得在 Opus、Fable 間互換來重置輪數。
+- **模型不可得／權限／額度失敗**與結果做錯分開記錄：只試一次可用備援，標「備援」且不算上述任務失敗輪。Fable 不可得可試 Opus；高階額度不足可試 Sonnet。備援仍不可用即回報，不循環呼叫。
+- 備援不降低驗收條件。指定模型不可替代、或能力不足以維持品質時，回報限制交 PO，不假裝完成。
+
+## 6. 驗收與作者分離
+
+**ai-team 任務一律由非作者輪流驗收，覆蓋一般低風險自查例外**；Tech Lead 自己執行也適用，全部通過後交 PO，不自行 commit。
+
+一般任務依 GLOBAL.md：低風險單點修改可由主 agent 命令＋read-back；高風險／跨模型成果需 fresh context 或跨工具獨立驗收，檔案交付須獨立 read-back，程式須跑測試或實跑。
+
+| 產物 | 驗法 | 適合驗收者 |
 |---|---|---|
-| 掃描、搜尋、read-back 驗證、格式檢查、機械批次操作 | `haiku` 或 `sonnet` | 判斷成分低，便宜快又夠用 |
-| 一般實作、重構、研究、審查等有判斷成分的工作 | `sonnet`，不確定時傾向 `opus` | 品質與判斷力優先於成本，但機械工作不必無條件上 opus |
-| 高風險判斷、架構取捨、對抗審查、第二意見 | `opus` | 換便宜的就掉品質的地方 |
-| 任務明確綁定 Fable 5（該次特殊 session／使用者指名） | `fable` | 日常不主動指定 |
+| 機械文件／格式 | 存在、完整、逐條 read-back | Haiku；有語意判斷改 Sonnet |
+| 程式碼 | 跑測試或實跑，附實際輸出 | Sonnet；高風險另加高階審查 |
+| 架構／制度／難以察覺的錯誤 | 找不符合條件之處、對抗性審查 | Fable fresh CLI；不可得時用可維持品質的非作者備援 |
 
-猶豫時：**寧可選貴一級**（2026-07-25 使用者裁定：品質優先於成本），但先看任務是不是機械／量大／對錯好驗——是的話便宜模型本來就夠、也更快，不必為了「求穩」全上 opus。
+獨立驗收 prompt 僅含產物內容／路徑、diff、驗收條件與可重現機檢證據，不附作者解釋或 TaskLog 推理段。同機 headless 的檔案讀取若受限，由 Tech Lead 提供完整內容與證據，不以口述摘要代替。要求「找不符合之處」，不誘導確認沒問題。

+## 7. 維護
 
-**定義：一輪＝一次模型執行。** 同一子任務的階梯上限＝4 輪：`haiku → sonnet → sonnet → opus`（從哪級起跳就走剩下的階梯；起跳 sonnet 最多 3 輪）。
-
-- **小模型（haiku）錯一次** → 直接升 `sonnet` 重派，不給第二次機會（重試同模型通常重複同樣的錯）。
-- **中階（sonnet）同一子任務連錯兩次** → 升 `opus`，且 prompt 必須帶**完整失敗軌跡**（兩次的做法＋錯誤輸出＋驗收差距），讓高階模型知道哪些路已死。
-- **opus 是最後一輪**：opus 仍失敗 → 立即停手，整理失敗軌跡回報使用者，不再重試。
-- **高階解出模式後** → 把解法寫成明確步驟，**降回便宜模型批次套用**到其餘同型案例。
-- **因額度失敗**（非任務本身出錯）→ 降一級續跑並記 journal，不代表任務難度判斷改變。

-## 6. 驗證不自驗
-
-**做的人不驗自己**。驗證一律派 **fresh-context** subagent（新開、不給寫作過程，只給產物路徑＋驗收條件）：
-
-| 產物 | 驗法 | 派誰 |
-|---|---|---|
-| 檔案／文件 | read-back：存在？完整？逐條對驗收條件？ | `haiku` |
-| 程式碼 | 跑測試或實跑，貼實際輸出（不是「看起來對」） | `sonnet` |
-| 高風險判斷 | 第二意見：換模型（或走 ody 換 AI）獨立再判一次；或多答案評審擇優 | `opus` |
-
-驗證 agent 的 prompt 要求它**找碴**（「列出不符合驗收條件之處」），不是「確認沒問題」——後者會順著點頭。

**派工鐵律（風險／獨立性判斷，工具中立）：**
