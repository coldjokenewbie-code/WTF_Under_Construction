# Reference Study（案例研究，全域版）

> 來源：南科再生水廠 2026-08-20~21 四輪退件教訓（專案版）＋ 2026-09-14 跨專案彙整（Drive 16 份、git_mirror 9 份報告、37 條 PO 裁定）＋ ChildrenFuture 首次全域實跑。專案層若有同名 skill，專案版優先。
> 三藏 2026-09-14 三項拍板：以南科版為底；**決策檔為必產物**；骨架只有一個。

## 第 0 步：把「要決定的事」定準（退件第一大原因＝混層）

動手搜之前，一次問完四件事；PO 不在線時**採假設並明標**在報告頂部橫幅與決策檔，不阻塞：

1. **決策層次——先命名，不選單**：用一句話定義本次研究管什麼、不管什麼。層次因專案而異，四個例子只是例子，不是選項：
   | 專案 | 曾出現的層次 |
   |---|---|
   | 實體印刷物（手拿板） | 畫風 ≠ 版面 ≠ 工藝 ≠ 載體 |
   | 兒童展場（ChildrenFuture） | 互動機制 ≠ 視覺風格 ≠ 硬體載體 |
   | 導覽 app | 資訊架構 ≠ 互動模式 ≠ 視覺風格 |
   | 影片配樂 | 音樂風格 ≠ 聲畫對位 ≠ 授權來源 |
   | 紀錄片文件頁 | 敘事手法 ≠ 視覺呈現 |
   題目同時碰到兩層 → 拆成兩次研究，或把第二層定成固定條件寫進派工單。
2. **情境條件**（案例的適性檢核，由本次定義；「載體一致」只是視覺物的其中一條）：觀看距離、停留時間、觀眾年齡、有無引導、審查者、場地明暗、預算級距。**前提未問就推定必退**（暗場當亮場的實例）。
3. **判準**：PO 的評比軸，後面比較表以此為列。
4. **取樣比例**：預設六成本案領域＋四成跨界典範（PO 2026-06-10 拍板），可覆寫。

PO 說「補強」多半指**換研究層次**，不是加案例數——先確認再動。

## 案例入選鐵則（一票否決）
- **看得到作品本身**：方法論文章、哲學評論、獎項新聞稿、色票資源庫、公司首頁、工作室簡介一律不收。
- **情境條件一致**（第 0 步定義的那組）。
- **相關度分級**：高／中／僅參照，高相關優先。
- **寧缺勿濫**：不足目標數如實回報缺口與原因；弱案主編級剔除並在報告聲明剔了幾案、為什麼。
- **每軸刻意拉開光譜**，可含明確標示的下限對照組與反面教材。
- **反偏見四條**（全文與證據見 `<WTF_ROOT>/wtf-config/anchors/美學偏好側寫_2026-09-17.md`，第 0 步四件事定準後才引用）：
  1. 每軸至少 1 案**拓展組**：刻意違反 PO 已知偏好但品質確實高，卡片寫「違反哪一條、為什麼仍值得看」。
  2. 深色／高飽和／高密度案例**不得因色調或密度剔除**；剔除理由只允許三種：載體不符、語意不符、來源不可驗，逐案寫明。
  3. AI **不替 PO 預先過濾**：判斷「PO 大概不喜歡」的高相關案一律入選並標**爭議組**，不得沉默剔除。
  4. 決策檔必附**「刻意違反清單」**節：本輪放了哪些拓展組／爭議組案、對應側寫哪一列。缺這節視同未完成。
  PO 2026-09-17 已裁定三條**不是通則**：光明莊重只限法規／公務語域；teamLab 類沉浸風載體相符即可入選；以圖為主只限視覺型交付物、資料型不適用。不得把這三條當預設剔除理由。
- **跨軸重複提名由主編歸屬一次**（Connected Worlds 三軸皆提的實例），卡片標「跨軸」。

## 圖與動態證據
- 每案附**作品代表圖**，取得順序：og:image／twitter:image → 內文最大圖（排除 logo、icon、sprite）→ 長頁截圖挑彩度最高橫帶。**絕不用網站首頁 viewport 截圖。**
- 圖片直鏈逐條 `curl -sIL -A "Mozilla/5.0"` 驗 200＋image/*，下載壓縮（寬約 720px JPEG）存報告旁 `shots/`，報告引用本地檔。
- **contact sheet 逐張目視 QC**（標題對圖錯位、抓成 logo、抓成人物照都在這步抓）。
- **機制／動態類案例單張截圖不算數**，必附影片連結（YouTube oEmbed 驗標題）或 GIF 直鏈。YouTube 縮圖 `https://i.ytimg.com/vi/<id>/maxresdefault.jpg`，退而求 `hqdefault.jpg`；hqdefault 可能回灰色佔位圖，目視 QC 要抓。

## 驗證紀律
- 連結全數實開驗證，只出現在搜尋摘要的不算（AGENTS.md 鐵則）。**子代理回報的來源頁，主 agent 至少 HEAD 驗**；403 標「站方封鎖」、改第三方報導佐證，不得臆測連結。
- WebSearch 配額用罄：站內搜尋直抓、官方站直 fetch、archive.org（帶 referer）。
- 統計數值一律標期間與口徑（`playbooks/data-citation.md`）。
- 報告末附**驗證聲明**：驗證方式與日期、來源頁狀態、缺口、剔除數、去重、版權（圖僅供內部研究）。

## 分工（子代理）
- 每軸／每方向一個子代理平行；派工單必含：決策背景與退件教訓、入選鐵則、情境條件、驗證方法、回報格式（逐案結構化）、寧缺勿濫條款、限時。
- 回報後主 agent 做**主編級複核**：剔弱案、依實圖改寫與圖不符的描述、補抓更好的代表圖、跨軸去重。
- 需實開 URL 的研究**只在本機跑**，雲端 session WebFetch 一律 403。
- AI 評審分數不當交付門檻（系統性高估 3–4 分），只取其修改清單；視覺真相源＝截圖＋PO 目視。

## 產出（骨架只有一個）
1. **`index.html`**（供 PO 拍板）：用附件 `gen_case_report.py` 由 `cases.json` 產生——頂部假設橫幅、「怎麼讀」、一頁看完、每軸卡片 gallery（大圖點開影片、名稱、兩句性質、一句為何適用、相關度標籤、拓展組／跨軸標記、連結一律新分頁）、每軸總評四格（光譜／與判準相容／情境適性／產製成本）、綜合比較表（PO 判準為列、軸為欄、高中低 badge）、建議（標「供裁決非定案」）、待 PO 裁決清單、驗證聲明、勾選複製清單底欄。
2. **決策檔 `選型記錄_YYYY-MM-DD_主題.md`（必產物）**：第 0 步假設、各軸評分與一句理由、定案建議、被砍項與理由（三種理由之一）、不採納項與理由、**刻意違反清單**、待 PO 裁決、流程紀錄。報告本身不當終點。
3. 交付：`/usr/bin/open -g` 背景開啟；報告與 `shots/`、`cases.json`、決策檔同資料夾放 `workingfiles/案例研究_YYMMDD_主題/`；舊版進 `archive/`。
4. **PO 打回或挑選後**：同一工作階段內把落選版與獲選版寫成一對錨點進 `wtf-config/anchors/`（README 規則），一句話判準寫差異在哪，禁寫「使用者偏好」。

給 PO 拍板的 HTML 研究報告，與給業主的正式報告書（docx／pptx，章節照需求書、註腳格式、清除內部路徑）是兩套格式，不可混用。

## 已知失敗模式（每一條都真的發生過）
1. 決策層次混淆（版面、工藝、載體當「視覺美術」交出去）→ 退件。
2. 首頁截圖當案例圖 → 「無參考價值」退件。
3. 單張截圖交代動態機制 → 退件。
4. 情境條件不一致（動畫／投影案例支撐印刷板；亮場前提用在暗場）→ 退件。
5. 湊數：香水瓶、個人習作、無關主題塞進清單 → 整份可信度崩。
6. 代理描述與實圖不符 → 逐張看圖後再寫。
7. 子代理來源頁只憑搜尋摘要、手寫的 App Store 連結錯 5 條 → 主 agent HEAD 驗、走官方 API 取 URL。
8. 內部註記塞進給業主看的檔 → 「很難閱讀」。
9. macOS 無 `timeout` 指令：批次擷圖用 python subprocess timeout。
10. 把「PO 可能不喜歡」的高相關案例事先濾掉 → 研究只是在證實既有偏好，失去拓展價值。
