# /heart-beat — 定時心跳回報

用法：
- 對話中說「心跳」即啟動，**預設 n＝3 分鐘**；說「n 分鐘心跳」（例：「5 分鐘心跳」）則覆寫。套用到當前這批任務。
- `/heart-beat [n] [任務描述]` — 顯式啟動，n 為分鐘數，省略＝3。

來源：PO 2026-08-14 裁定之「n 分鐘心跳」規則。該條原文於 2026-08-20 由 PO 自 `AGENTS.md` 移除，**規則本文自此以本 skill 為準**（AGENTS.md 不再重複）。

## 核心規則

任務全部完成、或使用者喊停之前，**每 n 分鐘輸出固定一行使用者看得見的心跳**：`HH:MM｜一行進度｜預估 HH:MM 完成`。

**心跳判準：只呼叫排程／等待工具（ScheduleWakeup、Monitor 等），但該回合沒有輸出文字＝心跳失敗。** 心跳必須是回合裡實際打出來的那一行，不是工具呼叫本身。

**心跳行只有進度。** 心跳回合若另有子代理結果、裁定、待決事項，**另起段落寫，不併入心跳行**（PO 2026-09-15 裁定）。

## 執行機制

1. **啟動**：記錄起始時間。用 Bash 執行 `date +%s`，把結果當作 `last_beat_ts`；同時記下 `interval_sec = n*60`。不必寫檔，記在對話狀態裡即可（多輪對話靠自己追蹤，不依賴外部計時器）。
2. **推進中**：每次要執行下一批動作前，先用 `date +%s` 讀目前時間，減去 `last_beat_ts`：
   - 差值 `< interval_sec` → 不用心跳，正常做事。
   - 差值 `>= interval_sec` → **先輸出一句心跳文字**，再繼續做事；輸出後把 `last_beat_ts` 更新為現在。
3. **心跳行格式**：固定三欄 `HH:MM｜一行進度｜預估 HH:MM 完成`，全行 50 字內。時間戳用 `date +%H:%M` 實取；預估寫**絕對時刻**，不寫「還要幾分」。例：
   - `14:32｜批次 4 sonnet 視覺複驗中｜預估 14:45 完成`
   - `09:07｜素材生成 4/6 張｜預估 09:12 完成`
4. **任務完成當回合**：不用心跳格式，直接照一般結束流程回報結果即可。
5. **停止條件**：任務全部完成，或使用者明確喊停（如「不用心跳了」「先停」）。

## 已知失敗模式（不要踩）

- **只排程不出聲**：呼叫 ScheduleWakeup／Monitor 等待工具、但該回合沒有任何文字輸出 → 使用者看不到任何進度，視為心跳失敗。這類工具本身不算心跳。
- **單一長工具呼叫吞掉心跳窗口**：若某一步驟（大型 Agent 派工、長跑 Bash、大量檔案處理）預估會超過 n 分鐘且中途無法插入文字，先在啟動該步驟前告知使用者「這步驟預估約 X 分鐘，期間心跳會延後到它結束」，避免使用者誤以為卡住。
- **多任務並行時心跳失焦**：用 Agent fork／Workflow 派多個子任務時，心跳由主對話 agent 統一彙總各子任務進度回報一句，不是每個子 agent 各自對使用者心跳。
- **心跳內容空洞**：避免只寫「處理中」；沒有具體進度可講時，進度欄寫「卡在＜哪一步＞」，仍只一行，不擴寫原因或裁定。
- **把裁定或結果塞進心跳行**（2026-09-15 實例：sonnet 複驗裁定整段當心跳送出，無時間戳、無預估）→ 心跳行只留三欄，其餘另段。
