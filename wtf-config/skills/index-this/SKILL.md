# /index-this — 記進 INDEX.md

用法：`/index-this <要記錄的內容>`

適用情境：GLOBAL.md「INDEX 鐵律」的例外——**使用者拍板的決策點可短列在 INDEX**，不必為此另建 TaskLog。其餘進度/待辦仍以當前 TaskLog 為真相源，不用本 skill 塞進 INDEX。

## 執行步驟

1. **取得內容**：`/index-this` 之後的文字即為要記錄的內容。

2. **內容為空時**：向三藏詢問要記錄什麼（一句話問清楚，不用選項式提問——內容是自由文字，非多選）。
   - 三藏回覆給出內容 → 進入步驟 3。
   - 三藏這輪仍未給出具體內容（跳過、說不用了、答非所問）→ 回報「已忽略本次 /index-this，未寫入」，結束，不建立、不修改任何檔案。

3. **決定寫入位置**：
   - **預設**：當前工作目錄所屬專案的 `_context/INDEX.md`。
   - 三藏訊息中另有指示（例如指名別的專案、別的路徑）→ 依三藏指示為準，不套用預設。
   - 目標專案的 `_context/INDEX.md` 不存在 → 告知三藏尚未建立此檔，詢問是否要建立最小骨架（標題 + 「最後更新」列）後再寫入，不要自行假設建立。

4. **寫入格式**：遵照該 INDEX.md 既有慣例——新條目插入檔案最上方（最新在前），格式比照現有條目（日期標題 + 一句話內容；若三藏提供的內容本身已經是完整一句話，直接採用，不額外加工延伸）。同步更新檔案開頭的「最後更新」日期為今天。

5. **完成回報**：一句話講清楚寫進了哪個檔案、記了什麼內容。commit／push 依當下慣例（`/session-end` 或使用者要求時再處理，本 skill 本身不強制立即推送）。

## 注意事項

- 本 skill 只寫 INDEX，不建立、不覆蓋 TaskLog；若三藏描述的內容明顯是完整工作紀錄（有多個步驟、待辦），提醒三藏這應該走 TaskLog 而非 INDEX 短記，兩者是不同真相源。
- 不得把 INDEX 當成待辦清單複製貼上——只記快照式的一句話決策/現況，避免與 TaskLog 內容重複而漂移（呼應「INDEX 鐵律」）。
