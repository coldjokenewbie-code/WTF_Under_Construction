# W_Doc_Guard（共編檔守則）

來源：GLOBAL.md「共編檔鐵律（`W_` 前綴）」，2026-08-14 PO 裁定。本 skill 是該規則的操作化版本。

## 觸發條件

要新增內容、修改、或用腳本重建**任一檔名以 `W_` 開頭的文件**時，先套用本守則。這類檔案定義為「使用者與 AI 共編」，**預設使用者可能已在檔案上直接編輯過**，不論當下對話有沒有提到。

## 核心規則

1. **禁止用產生器／整檔重建腳本改檔**：任何「讀模板／讀資料 → 整份重新產出覆蓋原檔」的作法一律禁止，會把使用者手動編輯的部分連同覆蓋、無法復原。
2. **動手前先重讀檔案最新內容**：不能沿用對話 context 裡先前讀過的舊版本。以實際儲存位置的最新存檔版為準（Claude_cowork 專案＝ Google Drive 上的版本，不是 git_mirror 端可能落後的複本）。
3. **只做就地增量修改**：定位到要改的段落，用局部編輯（等同 Edit 工具的字串替換），不重寫整份檔案內容，不做「先刪除全文再貼上新版」這類動作。
4. **改前備份**：動手改之前，把當下版本複製一份到該檔案所在目錄的 `archive/`（不存在則建立），檔名附時間戳或版本標記，確保使用者的既有編輯有留痕可還原。

## 使用者說「我已編輯」時

無條件視為觸發訊號——即使當下看起來檔案內容跟自己記得的一樣，仍要重新讀取一次確認，不可憑對話記憶直接動手。

## 已知失敗模式（不要踩）

- **憑對話裡的舊版內容直接改**：中間使用者可能已經另外存檔，對話 context 裡的版本已經過期，改下去等於用舊版覆蓋新版。
- **用「重新生成整份文件」代替局部修改**：即使只是想調整一小段，只要走的是整檔重建路徑（模板引擎、產生器腳本、整份 Write 覆蓋），就是本守則要擋的行為，改用鎖定段落的增量編輯。
- **跳過備份直接改**：沒有備份，一旦增量修改判斷錯段落或使用者事後想找回舊版，沒有任何復原依據。
