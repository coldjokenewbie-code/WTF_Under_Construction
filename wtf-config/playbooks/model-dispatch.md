# 模型調度守則
> 適用：Claude Code（含 web/remote）；跨工具派工使用 `skills/ai-team`，Codex／Antigravity 參數依各自工具 schema。
> 目的：按錯誤代價、可驗收性與協調成本派工，品質條件不變，避免同角色重複使用高階額度。
> 觸發：要派 subagent、選模型或 effort、升降級時讀本檔；是否適合派工先依 GLOBAL.md。

## 0. 型號與參數（2026-09-14 本機查證值，會過時）

來源：PO 指定交接文件 `Handover_2026-09-14_ai-team跨工具skill與模型調度優化.md` 的 V4/V5：Claude Code session 系統提示與 Agent tool `model` enum。這是該 session 的可用值，不保證所有帳戶、工具或版本都可呼叫。遇到拒絕時讀當前 schema／錯誤，不憑訓練記憶補型號。

| 稱呼 | Agent `model` | 模型 ID（CLI/API 識別） | 定位 |
|---|---|---|---|
| Fable 5.1 | `fable` | `claude-fable-5-1` | 高錯誤代價判斷、跨檔診斷、第二意見、獨立驗收 |
| Opus 5 | `opus` | `claude-opus-5` | Claude 搭檔的主對話基準，耦合修改、架構與制度判斷 |
| Sonnet 5 | `sonnet` | `claude-sonnet-5` | 一般實作起點、讀取密集搜尋摘要、測試 |
| Haiku 4.5 | `haiku` | `claude-haiku-4-5-20251001` | 格式轉換、可逐字驗證的批次任務 |

主 agent 由 PO／當前工具決定，不強制改成 Opus；例如本次制度優化由 Codex 擔任 Tech Lead。Agent 使用短值，`claude -p --model` 使用完整模型 ID。

**effort**：2026-07-03 歷史查證中，Claude Agent tool 沒有逐次呼叫的 effort 參數；逐次使用前以當前 schema 為準。不要把其他工具的 `effort` 參數直接套到 Agent。未確認的設定與額度歸屬寫「未驗證」，不以模型名稱推定價格或共用額度池。

**排程模型與額度**：排程主模型與任務中派工模型是不同設定。2026-07-08 的 Routine UI／MCP 限制屬歷史紀錄，當前行為未驗證；遇到額度或模型不可得，依第 5 節處理，不假定排程會自動備援。

## 1. 派工判斷

**第 0 步分流（2026-09-17 PO 裁定，全文見 GLOBAL.md 派工鐵律）**：先判「需不需要高階」。不需要→低階直接做；需要→高階只策劃、拆解、驗收，執行交低階。CP 值優先但驗收不降；低階做不來就升級。派工紀錄必寫模型階層與理由。


以下是候選訊號，不是單憑行數強制派工；優先遵守 GLOBAL.md 的獨立性與耦合判準。

| 情境 | 處理 |
|---|---|
| 預估閱讀 >300 行／>3 檔，或不確定在哪裡的搜尋 | 可獨立完成時派 Explore，主對話收結論＋檔案:行號 |
| 多檔機械替換、格式檢查 | 有明確驗收條件時派 Haiku／Sonnet |
| 高度耦合的跨檔修改、需反覆討論的小修 | 主 agent 自做，避免交辦成本高於執行 |
| 已知位置的單點讀寫、單一命令、與 PO 的判斷 | 通常主 agent 處理 |

## 2. 任務交辦三要素（缺一不派）

1. **目標與動機**：要什麼、為什麼；提供執行所需脈絡。
2. **驗收條件**：可逐條核對的完成判準與允許修改範圍。
3. **回報格式**：結論、證據、限制與長度；範本見 `delegation-templates.md`。

## 3. 回報合約

- 第一行說明成功、失敗或部分完成；每個事實附檔案:行號或實際命令輸出。
- 主對話只收結論與判斷；長產物存檔回路徑，不貼大段原文。
- 預設最多 120 行，交辦可另訂；失敗需說卡在哪、已試什麼，不捏造成功。

## 4. 明確指定模型、管道與額度判準

| 任務型態 | 模型 | 管道 | 額度判準 |
|---|---|---|---|
| 機械、格式、可逐字驗證的批次操作 | `haiku` | Agent tool | 判斷少且驗收便宜；需要語意理解才用 Sonnet |
| 讀取密集搜尋、摘要 | `sonnet` | Agent tool／Explore | 只回結論＋檔案:行號；若漏判難以察覺，升高階 |
| 一般實作、單點修改與測試 | `sonnet` | Agent tool；耦合高時主 agent 自做 | 先看錯誤是否可由測試發現，避免每次單點修改都派高階 |
| 耦合修改、架構與制度判斷 | 主 agent；Claude 搭檔可用 `opus` | 主對話或 Agent tool | 品質優先；協調成本高時不拆分 |
| 高代價設計、跨檔診斷、第二意見 | `fable` | Agent tool，`model: fable` | Sonnet 結論若錯且主 agent 不易發現，才使用高階；交辦必要脈絡 |
| 高風險成果獨立驗收 | Fable 5.1 | `claude -p --model claude-fable-5-1 "<prompt>"` | 需要新的對話；只給產物、diff 與自足驗收條件，不帶作者推理 |
| 跨程序／排程判斷任務 | 依風險選；需高階時 Fable 5.1 | `claude -p --model claude-fable-5-1 "<prompt>"` | 每次交辦自足；搜尋摘要不因可用 CLI 就升級 Fable |

- Opus／Fable 是高階選擇，不是固定高低階梯。依任務適配與獨立驗收需求選擇，不宣稱未量測的能力或價格優劣。
- 同任務同角色不並派兩個高階；執行者與獨立驗收者可各使用高階。高階找出模式後，將明確步驟交回較低成本模型批次套用。
- Agent 是否繼承 context 依當前工具決定；fresh CLI 仍可能載入相同制度，獨立驗收靠隔離作者推理及實際證據，不保證換模型就無偏誤。
- 原始字元數不等於 token 或帳單：實際注入、快取與載入方式均影響費用。減少重複背景、合併獨立查詢，實際費用未取得時明說。

## 5. 升級與備援上限

**一輪＝一次實際任務執行**。同子任務最多 4 輪：`haiku 1 → sonnet 2 → 高階終局 1`；從 Sonnet 起最多 3 輪，從高階起只有 1 輪。

- Haiku 錯一次就升 Sonnet；Sonnet 第二次必須換方法並重寫交辦，不能原 prompt 重送。
- Sonnet 兩次仍不符條件，帶完整失敗軌跡（方法、輸出、驗收差距）交 Opus 或 Fable **二選一**終局處理。
- 高階仍做錯 → 停止自動重試，回報證據與待決；不得在 Opus、Fable 間互換來重置輪數。
- **模型不可得／權限／額度失敗**與結果做錯分開記錄：只試一次可用備援，標「備援」且不算上述任務失敗輪。Fable 不可得可試 Opus；高階額度不足可試 Sonnet。備援仍不可用即回報，不循環呼叫。
- 備援不降低驗收條件。指定模型不可替代、或能力不足以維持品質時，回報限制交 PO，不假裝完成。

## 6. 驗收與作者分離

**ai-team 任務一律由非作者輪流驗收，覆蓋一般低風險自查例外**；Tech Lead 自己執行也適用，全部通過後交 PO，不自行 commit。

一般任務依 GLOBAL.md：低風險單點修改可由主 agent 命令＋read-back；高風險／跨模型成果需 fresh context 或跨工具獨立驗收，檔案交付須獨立 read-back，程式須跑測試或實跑。

| 產物 | 驗法 | 適合驗收者 |
|---|---|---|
| 機械文件／格式 | 存在、完整、逐條 read-back | Haiku；有語意判斷改 Sonnet |
| 程式碼 | 跑測試或實跑，附實際輸出 | Sonnet；高風險另加高階審查 |
| 架構／制度／難以察覺的錯誤 | 找不符合條件之處、對抗性審查 | Fable fresh CLI；不可得時用可維持品質的非作者備援 |

獨立驗收 prompt 僅含產物內容／路徑、diff、驗收條件與可重現機檢證據，不附作者解釋或 TaskLog 推理段。同機 headless 的檔案讀取若受限，由 Tech Lead 提供完整內容與證據，不以口述摘要代替。要求「找不符合之處」，不誘導確認沒問題。
