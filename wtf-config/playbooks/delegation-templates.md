# 任務交辦 prompt 範本
> 適用：Claude Code 主對話派 subagent（Agent tool）時直接複製填空。`｛｝`＝必填，`（）`＝視情況
> Codex／其他工具的 subagent 呼叫介面不同，不可直接沿用本檔範本（見 model-dispatch 對應工具轉接層）。
> 配套：門檻與 model 選擇見 `playbooks/model-dispatch.md`；驗收判準見 `playbooks/judgment-rubrics.md`
> **2026-07-25 改版**：依 context-engineering 新規則「範例限縮模型探索空間，介面設計才傳達用法」——範本只給**介面**（輸入/輸出/約束/驗收），不給實作步驟或成品範例；先例只給路徑供歧義時查閱，不貼內容當範本模仿。
> 通則：每份範本三段固定——目標與動機／驗收條件／回報格式。派工時三段都要填，缺就補完再派

## 通用回報合約（每份範本結尾都附上這段，原文照貼）

```
回報要求：
- 第一行＝一句話結論（完成／失敗／部分完成＋主因）。
- 只回結論與判斷，每個事實附 檔案:行號。禁止貼大段原文。
- 長產物（>50 行）存檔到 ｛存放路徑，預設 outputs/_shared/｝，回傳路徑。
- 回報總長 ≤120 行。
- 失敗就寫失敗＋卡點＋已試過什麼，不要硬掰。
```

**若用 Workflow 的 `agent(prompt, {schema})`**（非 Agent tool，見 model-dispatch）：上段 prose 可整段省略，改用結構化 schema 強制輸出格式，欄位本身就傳達規則，不必文字叮嚀：
```js
{
  status: "done | failed | partial",
  conclusion: "一句話",
  facts: [{ claim: "...", evidence: "檔案:行號" }],
  artifacts: ["路徑"],
  blockers: ["失敗才填，成功留空"]
}
```
`evidence` 必填即強制「每個事實附證據」；`blockers` 存在即傳達「失敗要老實說」——介面設計取代文字提醒。

## T1. 搜尋／定位（agent: Explore，model: haiku 或 sonnet）

```
在 ｛repo/目錄路徑｝ 找 ｛要找什麼：定義/用法/設定/資料流｝。
動機：｛我拿到結果要做什麼｝。
範圍提示：（可能在 ｛目錄/檔名模式｝；已知線索：｛關鍵字/函式名｝）
驗收條件：
- 列出全部命中位置（檔案:行號），漏一處算失敗。
- 每處一句話說明它是什麼角色。
- 無論有沒有命中，都要交代用過哪些搜尋詞／查過哪些目錄（不是只在找不到時才報告）。
```

## T2. 實作（agent: general-purpose，model 見 model-dispatch）

```
目標：｛做出什麼，一句話｝。
動機：｛為什麼要做、給誰用——遇到規格沒寫到的情況，照這個動機取捨｝。
輸入介面：｛SSOT/規範檔路徑（唯讀）｝＋｛需要的資料/術語表路徑｝
輸出介面：｛檔案放哪、命名格式｝
硬約束（不可逆項）：除 ｛allowlist 檔案/目錄｝ 外不得改動任何檔；｛其他不可退讓的邊界｝
驗收條件（逐條可勾，用可執行命令表達，不用「做好做滿」這類形容詞）：
- ｛條件1，例：X 檔存在且 python3 x.py --check 回傳 0｝
- ｛條件2，例：既有測試全過：跑 ｛測試命令｝｝
- 每條驗收附「驗證命令＋實際輸出摘要」，只寫「已確認」不算。
先例（若有）：｛路徑，需要時自己去讀，不貼內容在此當範本模仿｝
```
「怎麼做」（用什麼函式庫、演算法、步驟順序）交給模型自己判斷；只有已知的踩坑結論（gotcha）才寫進規範檔，不要在 prompt 裡示範步驟。

## T3. 重構（agent: general-purpose，model 見 model-dispatch）

```
目標：把 ｛目標檔/模組｝ 重構為 ｛目標狀態｝，**外部行為不變**。
動機：｛例：重複邏輯三處，之後要加功能會改漏｝。
安全網（先做再動手）：
- 先跑 ｛測試/驗證命令｝ 記下基準輸出；沒有測試就先寫「行為快照」（輸入→輸出對照表）存 ｛路徑｝。
- 小步走：每完成一個獨立步驟就重跑驗證，壞了立刻回退該步，不累積未驗證的改動。
禁改清單：不動 ｛公開介面/檔案清單｝。
驗收條件：
- 重構後 ｛測試/快照｝ 與基準完全一致（附前後輸出對照）。
- diff 只含 ｛允許的範圍｝，git diff --name-only 逐行核對。
- 行為有任何刻意改變＝失敗，回報而不是順手改。
```

## T4. 研究（agent: general-purpose，model 見 model-dispatch；高風險結論考慮升級）

```
問題：｛要回答什麼，一句話＋判斷成功的樣子｝。
動機：｛這答案要支撐什麼決策｝。
方法要求：
- 來源優先序：｛官方文件/repo 內檔案/實測｝ > 部落格轉述；每個結論標來源（URL 或 檔案:行號）。
- 網路連結必須實際開啟讀過才能引用（AGENTS.md 規定），只出現在搜尋清單的不算。
- 查不到就寫「查不到」＋查過哪裡，禁止用訓練記憶補——特別是版本號、型號、參數名。
驗收條件：
- 回答問題本身（不是丟資料）；分「確認的事實／推測（標註）／查不到」三欄。
- 關鍵結論至少兩個獨立來源，或一來源＋一實測。
```

## T5. 審查（agent: general-purpose，model 見 model-dispatch；高風險判斷可用第二意見）

```
審查對象：｛檔案路徑清單 或 git diff 範圍｝。
你是 fresh-context 審查者：不要假設作者是對的，你的任務是**找碴**，找不到問題也要證明找過。
審查維度（逐項過）：
- 對照驗收條件：｛原任務的驗收條件逐條貼上｝
- 引用完整性：檔內引用的路徑/命令/工具名，逐一 ls/實測確認存在。
- 矛盾檢查：與 ｛相關檔案，例：GLOBAL.md、同目錄其他規則｝ 有無互相打架。
- ｛特定關注點｝
用 ReportFindings 工具回報（不是文字清單）：每條 finding＝檔案:行號＋一句話缺陷＋失敗情境；嚴重度由高到低排序；沒問題的維度仍要能證明「查過」（ReportFindings 找不到就回空陣列，不必額外寫「查過無發現」的文字，空結果本身就是證據）。
```

## T-視覺／品味類任務（agent: general-purpose，model 見 model-dispatch）

視覺、意象、聲線、手感類任務**不適用**上面「不給範例」原則——品味與意象無法 schema 化，參照物是意圖的最高保真載體。三件套缺一不可，否則容易多輪退改：

```
目標：｛做出什麼視覺/聲音效果，一句話｝。
參照物（必附，至少一項）：
- 參考圖／參考音檔：｛路徑｝（這是規格，不是「風格類似」的模糊形容詞）
- 可跑的 HTML mockup 或既有頁面路徑：｛路徑｝（構圖/結構定錨）
判準（非逐 px/逐句複製）：｛例：版型沿用既有只調點名元素；聲線比對詞尾語氣，非逐字模仿｝
硬約束：不可動的元素/檔案｛清單｝
驗收 rubric（逐條可勾）：
- ｛例：與參考圖並排比對，構圖/明暗一致｝
- ｛例：與參考音檔並排播放比對，語氣/口音特徵一致｝
- 零 console error／零視覺回歸（既有元素未被誤動）
```
文字形容詞（「沉穩」「有流動感」「台味」）每個人解讀不同，參照物不會——這類任務給參照物不算「範例限縮探索」，是必要規格。
