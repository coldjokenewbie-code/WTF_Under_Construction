# 交付預覽、存檔與輸出格式
> 交付可看可聽成品、製作可存檔程式/網頁、選擇匯報格式前讀；來源：GLOBAL.md 原條文，2026-09-14 搬移。

## 交付即預覽

- **交付即預覽**（2026-08-20 擴大範圍：不限網頁）：交付任何可看可聽的成品（文件、圖檔、影片、音檔、網頁/HTML/圖表）時，主動用使用者系統預設軟體背景開啟，不用等使用者另外要求。**影片／音檔不可自動播放**：改用「在檔案總管/Finder 顯示」而非直接開啟播放器——macOS 用 `open -R "<檔案>"`、Windows 用 `explorer /select,"<檔案>"`，讓使用者自己點開播放。**批次產出（多個檔案）**：改開啟所在資料夾，不逐一開檔——macOS 用 `/usr/bin/open -g "<資料夾>"`、Windows 用 `start "" "<資料夾>"`。其餘單一可預覽檔案（文件/圖檔/網頁/圖表）：macOS 一律用絕對路徑加 `-g`：`/usr/bin/open -g "<檔案>"`（終端機如 cmux 會攔截裸 `open` 開進終端分割視窗，且 cmux 內建瀏覽器版面過於擁擠，不適合預覽）；Windows 用 `start "" "<檔案>"`；無 GUI 環境至少附可點的 `file://`／`http://` 連結，不能只給裸路徑。**`-g` 不可省略**（2026-08-20 PO 裁定）：裸 `open` 會把該 app 搶到前景、打斷使用者當下的工作，`-g` 才是條目所稱的「背景開啟」。另注意：若該檔使用者已在編輯器開著，`open` 只會把舊視窗叫到前面、不會重新載入，交付時要一併提醒重新載入。

## 存檔預設路徑鐵律

- **存檔預設路徑鐵律（2026-08-24 PO 裁定，2026-08-27 強化）**：凡是做出「可存檔／可寫回」的程式或網頁，檔案選擇器的**預設位置一律指向該檔案應該存放的目標資料夾**，不得讓使用者自己去找路徑。第一次選定後把 handle 存 IndexedDB，之後直接寫回同一位置、不再跳窗。無法預設到精確位置時，至少在按鈕旁明示目標路徑全文。**判準**：使用者若得自己翻資料夾才能存到對的地方，就是沒做完。
  - **檢核／勾選類網頁＝覆蓋原檔，不是另存新檔**：存檔目標永遠是它自己資料夾內的既有狀態檔，UI 用語寫「覆蓋」不寫「另存」。
  - **預設位置禁止落在系統「文件／Documents」**（downloads／desktop 同理）：`startIn` 不得寫 `'documents'`；沒有可用 handle 時寧可不給 `startIn`，並在按鈕旁附「複製資料夾路徑」按鈕＋走法說明（macOS 對話框按 ⌘⇧G 貼上、Windows 在檔名欄貼完整路徑），讓使用者一步跳到目標夾。**判準補充**：使用者若在對話框看到「文件」而得自己翻回專案資料夾，就是沒做完。
  - handle 存進 IndexedDB 後**必須於頁面載入時預讀成變數**，不可在 click 事件內才 `await` IndexedDB——那樣會失去使用者手勢資格，picker 直接開不起來。
  - 實作寫法與常見失敗見 `pitfalls-frontend.md`「檔案存取（FSA）」節。

## 輸出格式

- **輸出格式**（2026-07-25 改：範圍限縮）：agent 向使用者（PO）本人匯報用的文件，優先使用 HTML（`.html`）；輸出前若存在 `rules/html-preferences.md` 先讀完再動筆。**業主／廠商端的正式交付物不受此限**，依各專案慣例（docx/pptx 等）——先前「文件輸出一律 HTML」誤把匯報格式與交付物格式混為一談，兩者分開。

## 審閱頁交付（PO 2026-10-05 裁定，提交三藏審閱的 HTML 一律適用）

- **一份工作一個審閱頁、固定網址**：同一製作過程的各輪版本都收在同一個 HTML，不為每輪另開新檔。頁首放目錄（錨點），至少分「目前版本／選項比較／待審與下一步／過去版本」；過去版本集中在一區，PO 需要時再去看。
- **被 PO 判很糟（約 5 分以下）的版本不放審閱頁**，連過去版本區也不放；檔案留 `archive/`、經過記在 TaskLog 即可，不給 PO 看。過去版本區只放 PO 未否決、可能回頭參考的版本。
- **局部修改有多個選項時，用分頁籤（tab）並排在同一頁**，不另做新頁。
- **不要一直開新視窗或分頁**：交付時先找瀏覽器裡是否已開著同一頁，有就重新整理該分頁（不搶前景），沒有才背景開新分頁。macOS＋Edge 用 `python3 <WTF_ROOT>/tools/review_page/reload_or_open.py <頁面路徑>`（以 AppleScript 比對分頁網址後 reload，找不到才 `open -g`）；其他瀏覽器或 Apple Events 被擋時，交付訊息改請 PO 在原分頁按重新整理，不另開。
- 圖片網址加 `?v=` 版號防快取；舊版圖檔移 `archive/` 後，過去版本區改指向 archive 路徑，不刪圖。

## 簡報式提報網頁（簡稱「三藏簡報」；PO 2026-10-27 裁定格式、2026-10-28 定名。提交三藏或內部審閱的報告型 HTML、制度提案一律用此格式）

- **順序**：封面（大標寫研究發現＋副標一行＋4 格關鍵數字）→ 結論總覽（逐項對照原始需求，標已取得／部分取得／未取得，用表格）→ 每個需求項一張資料視覺化（大標寫結論、副標一行、圖下附出處與口徑、附表格檢視）→ 待決與下一步 → 正式報告全文（附件，放最後）。
- **形式**：投影片式單一 HTML，目錄＋鍵盤翻頁＋`#sN` 錨點；圖用內嵌 SVG，畫圖前先讀 dataviz skill 並跑色票驗證；大標、副標各一行，註記框不超過 3 行。範本：`<WTF_ROOT>/tools/review_page/template_review_slides.html`（複製自新竹科教館 2026-09-27 審閱彙報）。
- **讀者假設**：審閱者只大概知道案子、未參與討論，但熟悉所屬產業術語。不用內部 AI 協作術語與內部代號（三藏、PO、子代理、驗收 PASS、草稿章節號、檔名、R 代號）；待決寫「待內部決議」；產業術語不解釋，名詞說明另做一份給三藏的版本（同一腳本產出、加名詞頁、頁面明顯標示「給三藏看」）。交付前對全文 grep 禁用詞須為 0。
- **主詞與中立**：大標寫研究發現，不替本案宣傳；趨勢句先查規模與年代分層有無反例；未經內部決議的方案只做中立比較。
- 與上節「審閱頁交付」並用：同一工作仍只用一頁，過去版本放 `archive/`。
